# CtxAutopsy（上下文验尸官）

审计 agent 上下文压缩的**真实代价**：压缩报告"省了 X% token"时，账单真的省了吗？内容真的没坏吗？

全离线、零第三方依赖（stdlib）、纯确定性算法、无 LLM 当裁判。所有数字实测，可一键复现。

## 核心发现（本机实测）

**发现 1：省 token ≠ 省钱。** 用 DeepSeek 官方价推算本机 321 个真实会话（16,667 次 API 调用），缓存读占输入总量 **95.5%**。缓存命中价只有未命中的 1/30~1/50，所以压缩省下的多数是"便宜的 token"——对照实验中，滑窗压缩掉 83.6% 的历史，账单只降 2.2%；按词频删词反而让账单上涨（见下）。

**发现 2：压缩会静默损坏内容，且每种策略有自己的"作案手法"。** 合成任务对照实验（3 任务 × 5 策略 × 3 重复）：

| 策略 | 压缩率 | 约束损坏 | 否定词翻转 | 工具链截断 | 数值变形 |
|---|---|---|---|---|---|
| 截断（保头删尾） | ~50% | 有 | — | — | 有（丢失） |
| 滑窗（留尾部预算） | ~84% | 有 | — | **有（孤儿结果）** | 有（丢失） |
| 按词频删词 | ~27% | 有 | **有（最多 46 处翻转）** | — | — |
| 规则摘要 | ~29% | — | — | — | 有（约化） |

"否定词翻转"是真实文献现象的离线复现：83% 的约束破坏源于压缩器删掉否定词（Silent Inversion），因为"不/not"是最高频的词。

**发现 3：压缩破坏缓存前缀时，"省 token"会变成"涨账单"。** 实验中 6 个任务×策略组合出现压缩率 > 0 但账单反而上涨——压缩改写了历史前缀，下一轮全部按未命中价重写，省下的只是 1/30 价格的缓存读 token。

**发现 4（网关实证）：第三方网关加价 14 倍。** harness 自报成本 $478.92 vs 按官方价推算 $33.91（delta −92.9%）。这是实测差距，只报告不做归因——但它演示了本项目的核心方法：**账单必须用四档计费模型重算，不能信单一来源。**

## 架构（模块 A-E）

```
                    ┌─────────────────────────────────┐
  真实会话 jsonl ──▶ │ A. session_log 会话解剖           │──▶ 四档用量 + 构成桶
                    │    (usage 语义探测 new_only/total) │──▶ B. billing 四档计费
                    └─────────────────────────────────┘     (价格表可溯源可覆盖)
                    ┌─────────────────────────────────┐
  合成任务(确定性) ─▶ │ C. compressors 五个压缩策略        │──▶ 压缩产物 + 变更账
                    │    (作案者：不保护任何内容)         │──▶ D. checkers 四项验尸
                    └─────────────────────────────────┘     (约束/否定词/工具链/数值)
                    ┌─────────────────────────────────┐
                    │ E. experiment 对照实验             │──▶ CSV + Markdown 报告
                    │    (缓存模型 假设清单 A1-A7)       │
                    └─────────────────────────────────┘
```

设计分工：**C 是作案者**（压缩器对约束、否定词、工具链、数值一视同仁），**D 是法医**
（判定全部是确定性算法，唯一正确答案），**B 是账单**（价格全部有官方来源），
**A 是事实层**（真实日志解剖）。85 个 pytest 测试覆盖全部契约。

## 怎么跑

```bash
uv sync --dev                                  # 安装（仅 pytest 开发依赖）
uv run pytest                                  # 85 个测试

# 1. 解剖真实会话日志（只输出聚合数字，无消息文本）
python -m ctxautopsy analyze ~/.claude/projects --out experiments/real_session_report.md

# 2. 对照实验（3 任务 × 5 策略 × 3 重复 = 45 格，0.3 秒，全确定性）
python -m ctxautopsy.experiment

# 3. 单次验尸：对任意压缩前后对照跑四项检查
python -m ctxautopsy check --original o.json --compressed c.json --constraints x.json
```

## 技术决策（面试三层追问的答案）

**为什么检查器不用 LLM 当裁判？** 四项检查全都有唯一正确答案：约束保全 = 字符串级三态判定（PRESERVED/FRAGMENTED/LOST，n-gram 重叠率）；否定词 = 极性翻转判据（否定词被删且谓词头仍存活才算损坏，整段丢失归截断检查管，避免重复计数与误报）；工具链 = 结构配对（靠 tool_call_id 字段，不写死 id 正则，对任意后端格式稳健）；数值 = 规范化值贪心配对（66%↔0.66、62K↔62000 判保留，相对差 ≤10% 判约化，带"约"标记判 approx_word）。LLM judge 有随机性和自我偏好，确定性检查才能保证"同输入同输出"。

**缓存模型怎么敢说"结构对"？** 七条假设（A1-A7）逐条写进报告：单断点严格前缀是悲观下界、多断点是乐观上界，真实缓存位于两者之间；重放成本默认不计（离线无法确知 agent 是否真的重放）；所有 token 是 chars/4 估算口径。模型的承诺是"变化方向与量级对比"而不是复刻真实缓存——这个边界在报告第 3 节原文输出。

**为什么"省 token 反涨价"？** 缓存读价只有未命中的 1/30~1/50。压缩省下的 token 若来自缓存读（价格 0.15 元/M），省 1M 只省 0.15 元；但压缩改写前缀使下一轮缓存失效，同样 1M 按未命中价（4.5 元/M）重写一次，要 30 轮缓存读才能赚回来。按词频删词是"每处都改一点"的策略，前缀从第一条消息起就失效——所以它压缩率 27% 却让账单上涨。

## 诚实声明

- token 估算两套口径并存且用途分离：会话解剖用 CJK 感知估算（1 token/字），压缩切点与缓存模型用 chars/4——只做相对比较，绝对值不承诺准确
- 成本数字 = 实测用量 × 官方价格表（来源可溯源、快照日期标注、可用 JSON 覆盖）；harness 自报成本只作交叉参考，永不当真值
- 网关 usage 语义（new_only：input 不含缓存读）是本项目实测发现并自动探测的，报告里显式输出 `usage_semantics` 供人工复核
- 真实日志分析只落聚合统计；隐私由哨兵字符串测试守护
- 合成数据只用于策略横向对比；绝对数字以真实会话报告为准
